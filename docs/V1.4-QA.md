# V1.4 mobile canvas-first QA

## Baseline and scope

Started from `main` commit `3743464` (V1.3 PR #6). Only phone portrait at CSS widths ≤600px gets the new layout/type/chrome. Full-size iPad, desktop, and phone landscape retain V1.3. The approved Pindou mobile demo informed proportions and drawer placement; the other supplied references informed bitmap-like typography, HUD/resource chips, and tactile controls. No reference-game images/sprites were copied into the application.

## Implementation

- Header/tools → flexible SVG canvas → persistent coordinate arrows/Focus Step → collapsed drawer. The collapsed drawer is under 85 CSS pixels in tested views, with the canvas over 55% of each normal viewport. It holds placed/total, remaining count, compact swatches, and an expand indicator.
- Tap, keyboard Enter/Space, and vertical handle swipes operate the drawer. Its independently scrolling body contains selected-cell details/actions, step complete/clear, route controls (including Show Empty Steps), stats/positions and undo. Reopening resets the body scroll to the action area. Drawer pointer events never enter the canvas handlers.
- Phone Focus folds tools/zoom into the top HUD and frees the regular toolbar row. Exit Focus, adjacent navigation, and drawer access remain visible. Settings remain available in the drawer.
- Pixelify Sans is self-hosted (two Latin WOFF2 weights, about 16KB total) with its OFL license. Game-like chrome is scoped to phone portrait; chart text remains monospace and the vector grid receives no color filter.

## Sharpness investigation

V1.3 zoomed SVG through CSS `scale()` on an element with `will-change: transform`. Safari can cache transformed content at a layer's raster resolution; physical Safari blur could not be reproduced in this environment. The phone path now changes the SVG's actual width/height, with unscaled layout positioning for pan and no persistent compositor hint. SVG/viewBox and hit detection retain real rendered geometry; tablet/desktop rendering is unchanged.

Screenshot review also reproduced a native gray tap-highlight overlay across the SVG in Chromium. This transient browser tint is disabled on the phone stage, which already supplies a selection cursor. A screenshot-pixel assertion reads a solid bead fill after touch and compares RGBA with the project's original palette. This checks the rendered screenshot, not only an unchanged `fill` attribute.

### Reproduce the visual baseline

Use a source snapshot, not a new Git worktree. Export `3743464` into a temporary directory with `git archive`, provide its dependencies, and run its local build/preview. Against that preview:

```sh
CHROMIUM_PATH=/path/to/chromium \
PINDOU_TEST_URL=http://127.0.0.1:4201/pindou/ \
PINDOU_BASELINE_URL=http://127.0.0.1:4202/pindou/ \
npm run test:layout
```

The regular browser suite needs a running local dev server or production preview at `PINDOU_TEST_URL` (default port 5173). Use bundled Playwright Chromium if `CHROMIUM_PATH` is omitted.

## Required physical Safari follow-up

Automated Chromium is not physical-device certification. On an iPhone Safari build after review/merge:

1. Open a saved project and confirm the safe-area gap above the home indicator. Collapse the drawer; show/hide Safari's toolbar and verify navigation stays visible with no page scrolling.
2. Use 100%, 200%, 300%, and 500% pattern zoom, checking grid edges and codes both after pinch and after button/menu zoom. Pause after gesture end to look for a stale low-resolution texture; pan horizontally/vertically and compare again.
3. Tap centers/near edges in Select. Confirm the cursor identifies the intended bead, no whole-chart gray tint appears, no popup opens, and progress remains unchanged until an explicit drawer action.
4. Open/swipe/scroll/close the drawer at each zoom. Verify selected metadata, route settings, Mark/Clear Step, both undo actions, and updated remaining quantities. Rotate, return to portrait, then refresh and confirm saved cells/strategy remain.
5. Check Dynamic Type/browser text zoom and native safe-area behavior; headless tests do not emulate nonzero iOS insets or Safari compositor internals.

No physical Safari/iPad testing was available. Unusually long color lists may scroll horizontally in the summary and vertically in details. Pan preserves the zoom factor across layout changes, but the fit basis and positioning adapt to available viewport space. No schema migration, source-chart transcription, cloud synchronization, automatic merge, or manual deployment was introduced.
