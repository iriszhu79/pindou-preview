## Verification

The pipeline installs, unit-tests and builds every app, packages and checks all hashes, runs desktop/mobile smoke tests, audits localStorage reads/writes and Studio IndexedDB access, exercises source import/candidate uncertainty/review/undo/redo/autosave/ZIP export, and runs the existing current preview regression suites. Any required failure blocks upload and deployment.

The historical test:layout script requires a separate legacy main snapshot and asserts a pre-mobile-drawer layout; it is not a valid comparison fixture for these approved versions. Exact original-application file hashes plus current Workspace/mobile/selection/routes/crop/recognition tests provide the applicable unchanged-version regression checks. The flaky homepage-wheel precondition is synchronized only in exported test copies; approved application code and built assets are never modified for it.

Studio uses system fonts and currently has no Web Worker. Its JS/CSS and direct refresh are verified; consumer font/image/recognition-worker files are hash-checked and exercised. Live checks repeat the smoke suite and verify every live file against the packaged deployment manifest.

## Storage, privacy and acceptance

Studio's only IndexedDB database and LocalStorage preference namespace is pindou.annotation-studio.v1. Paths on github.io share an origin; namespace separation is not a security boundary. This is a public static tool, not an authenticated private server. This tool does not upload chart images or annotations; they remain in browser storage unless the reviewer exports them. Storage can be cleared/evicted; save and export backups regularly.

No P020 or benchmark corpus is hosted. Import the privately supplied P020 acceptance ZIP via Import; it restores as a new project, preserving existing annotations. All geometry/cell review states in that initial draft are unreviewed. Candidate RGB groups are not official bead codes. No bulk Ground Truth or OCR is generated by deployment.

Native Safari acceptance and mobile memory limits remain unverified. Large synchronous ZIP exports/history-heavy projects may pause or exhaust memory; begin with one P020-sized project and desktop exports. Simulated export failure/reload/renderer-crash tests established saved-data preservation, not an actual OOM/eviction guarantee.
