# Pindou V2.0-A — existing-chart recognition prototype

## Scope and review instructions

Feature branch: `feat/v2-recognition-a` in `iriszhu79/pindou-preview`.
Base: published V1.5 commit `19a4cfbccc2eedcf70eab12db4512f6bc00ee57b`.
Production inspected read-only: `iriszhu79/pindou`, main `bb8c23905c1cae8c0488b6100fe569acdb4d80ae`.
No Pages configuration changes, new hosting projects, production commits, or preview-main updates are part of this prototype.

Run locally:

```sh
git clone --branch feat/v2-recognition-a https://github.com/iriszhu79/pindou-preview.git
cd pindou-preview
npm ci
npm test
npm run build
npm run serve:preview -- --port 4305
```

Open `http://localhost:4305/pindou-preview/`, select **UPLOAD PATTERN**, then **Load original MARD sample** or upload a JPG/PNG. Run automatic grid detection, compare source/crop and digital cells, correct cells and palette codes as needed, explicitly acknowledge the review, then confirm into Overview and Start Beading.

Use a fresh browser profile or this separate local origin for prototype review. The storage format/key remains compatible (`pindou.preview.v15.projects.v1`). Recognition drafts do not write storage. Confirmation inserts a new UUID project, retains existing projects, and starts all its completion flags at false. Production's `pindou.projects.v1` is never read or written. Original image/confidence metadata remains in the review/export, separate from Workspace completion state. Export before leaving if the recognition evidence is needed; review drafts are not persisted.

## Architecture

- `src/recognition.ts`: pure raster/geometry functions, periodic-line grid detection, robust cell-background sampling, empty detection, limited-palette clustering, statistics, validation, Project conversion.
- `src/recognition.worker.ts`: off-main-thread analysis; UI can cancel and stale results are ignored.
- `src/RecognitionReview.tsx`: orientation-normalized browser decoding, white alpha compositing, crop/dimension controls, source/grid comparison, uncertainty outlines, per-cell edits/restoration, editable palette codes/names, review acknowledgement and JSON export.
- `src/recognition.css`: scoped cream/pixel-panel UI; side-by-side desktop comparison and switchable mobile views.
- `src/main.tsx`: upload entry, reviewed import handoff and accurate project labels. Existing Workspace logic/controls remain intact; recognition pages do not trigger project autosaves.

No image processing dependency, OpenCV download, paid AI API, cloud image upload or photo-to-pixel generation was added. This narrow regular-grid prototype does not justify OpenCV's distribution size; perspective correction and OCR remain separate future work.

Limits: JPG/PNG, 15 MB, 20 megapixels, at most 12,000px per side; at least 8px per cell; integer dimensions up to 300 per axis / 40,000 cells; at most 24 detected colors. Automatic detection requires at least six intervals per axis. Smaller grids may be specified manually. Limits and validation failures are shown rather than silently generating substitute data.

## Known limitations and next phases

- Regular square grids only. A recurring decorative/text pattern can produce a plausible wrong grid; every automatic crop needs visual review. Rotation/skew is not corrected; strongly inconsistent axis spacing is rejected. Manual crop is numeric, not a draggable quadrilateral.
- Median RGB/background clustering can merge similar shades or split compressed colors. Occupied white uses dark-ink density and can be confused with symbols or watermark marks. No calibrated semantic confidence, OCR, inferred missing cells, brand-code lookup or total-count correction.
- Users can edit existing palette codes/names and assign cells to detected colors; adding previously missing palette colors/bulk edits is future work. Only accepted structured cells persist in Workspace; export recognition evidence separately.
- Excessive palette size/blank/no-grid inputs fail with a correction path. This is not a universal photo detector; manual geometry must only be used on an actual chart.
- Browser tests cover Chromium emulation, not native iPhone/iPad Safari acceptance. Full-page screenshots prove local rendering only.

**V2.0-B:** build independently audited cell-level datasets (including white/empty ambiguity), add line-quality/skew diagnostics and stronger crop/hint fitting, calibrate uncertainty, add jump-to-uncertain/zoom and palette additions, benchmark Safari/mobile workers.

**V2.0-C:** add optional local legend/code OCR with evidence and user confirmation, better shade separation, batch correction and recognition-draft persistence/export-import. Retain the Project adapter and regression suite. Photo-to-pattern generation stays reserved for V3.0.
