# V1.3 QA — selection, shared progress and meaningful routes

## Inspected baseline

Latest `main` at the start was `fa86695` (merged V1.2 PR #5). Existing responsive viewport layout, Hand/Select gestures, Space pan, pinch/modifier-wheel zoom, strategy preview, rectangular grids, explicit step completion/undo, cell-based LocalStorage, and GitHub Pages configuration were retained.

## Reproduced causes and corrections

1. V1.2 accepted tap movement below five pixels, then mapped the **release** coordinate directly to a cell and toggled completion. A short drift across a small cell boundary could therefore complete the neighboring cell. Down and up now must map to the same valid cell; crossing a boundary cancels selection even below the drag threshold. Selection itself cannot mutate progress.
2. Native SVG hit testing was also observed in Chromium to quantize subpixel boundaries on downscaled cells around five CSS pixels wide. The final implementation uses the live SVG transform only when it agrees with actual rendered fill bounds. Otherwise it derives the address from the rendered origin and cell dimensions, incorporating CSS pan/scale, viewBox letterboxing and viewport changes. No device-specific offsets are used. Native hit testing only checks that the event is within the stage, not which cell owns it.
3. Browser test boundaries must use **fill** geometry: Playwright's SVG `boundingBox()` can include a stroke, placing an alleged crossing wholly inside a neighboring fill. Boundary tests use `getBoundingClientRect()` on the fill rectangle rather than an expanded stroke box. Tests do not offset expected coordinates to force a pass.
4. Strategies previously reset raw `step` to zero and navigation counted all physical rows/columns. Routes now project ordered nonempty coordinates from the same cell grid. New routes prefer unfinished steps; normal resumption preserves a valid nonempty position. A legacy empty position is redirected only when explicitly opening/resuming it. The studio's initial load does not rewrite storage.

These are confirmed code/Chromium observations. Physical iPhone Safari behavior was not available for root-cause confirmation, so this is not a claim that every Safari-specific cause was reproduced.

## State and visual behavior

- Selection is a temporary address. It survives tool/route/Focus/view changes, clears across project IDs or invalid data, and never appears in stored project records.
- Mark Selected Complete / Undo Completion changes exactly one nonempty cell. Step completion and navigation remain separate. Existing global undo remains available in Details.
- Original colors/codes remain visible. Selection uses a contrasting dashed outline/corners; completion adds a light badge with a dark check, readable on both light and dark fills.
- Normal workspace exposes strategy/direction and optional all-grid-coordinate navigation. Focus has a compact route menu, smaller side panel/folded dock actions, and more canvas space. Browser checks require over 8% more canvas area at each V1.3 viewport with inspection active.
- `Project.step` stays a directional grid offset for backward compatibility. The storage key, IDs and cell schema are unchanged. Nonempty task numbering is derived, not persisted as a different interpretation of old values.
- Memoized grid/step rendering and cached statistics/routes avoid rebuilding the SVG cell tree during every pan/zoom update.

## Limitations and follow-up

Automated Chromium input/viewport tests are not real-device certification. Verify physical Safari/iPad taps and pinch, native browser toolbar/safe-area behavior, browser zoom, and Mac trackpad feel on devices. The fallback assumes the supported axis-aligned translate/scale canvas, not future rotation/skew. Ambiguous cross-cell drifts intentionally do nothing; zooming in provides larger touch targets. No parser, guessed original-chart grid, cloud sync, Complete & Next, manual deployment, or automatic merge was introduced.
