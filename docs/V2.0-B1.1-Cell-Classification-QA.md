## Root cause and implementation

The previous sampler admitted a pixel only when **every RGB channel exceeded 145**. It therefore discarded valid saturated teal, orange, magenta, blue and black pixels along with text, and substituted gray when too few survived. Its separate empty test classified a near-white, low-channel-spread sample as empty. Teapot's pale cream lies near that threshold; compression and subpixel crop alignment changed which cream samples survived. The old first-match RGB clustering also retained the first cell as the palette representative.

`src/cellClassification.ts` replaces those decisions:

- Samples the interior 18–82% of each cell, avoiding borders. All RGB colors are valid candidates, including black. A quantized RGB mode identifies a dominant background, with perceptual support and nine independently sampled regions to resist text and watermark interference.
- Uses OKLab distance for representative support, palette assignment, merging and separation. A byte-channel transfer lookup avoids repeated exponentiation; it stores no source image data.
- Estimates bright neutral paper and its chromatic noise from perimeter cells, excluding tinted pale beads. This is independent of the dominant occupied color. A filled-pale synthetic chart prevents learning cream as empty paper.
- Decides occupancy before palette assignment: consistent multi-region background difference, centered printed marks for occupied white, or provisional empty. The remaining dark-pixel threshold measures printed-mark evidence only; it never rejects a dark bead color.
- Marks ambiguous pale/white and unlabelled white holes among beads for review. Close palette groups and outlying member colors lower color confidence. Confidence is heuristic evidence, **not calibrated recognition accuracy**.
- Combines weak whole-cell modes with a clear vote from multiple regions for an established palette group, without raising the sample confidence. Builds palette representatives from group medians, revisits strongly supported outliers to preserve rare colors, merges shading/compression variants, and preserves supported pale-versus-white separation. It does not force a group count or use legend quantities.

`src/recognition.ts` composes occupancy and color confidence, adds exportable reasons, and retains the existing temporary editable color codes. Review shows the selected cell's occupancy reason. Manual corrections update the new metadata; restore returns to the original analysis. Project conversion still saves the original Project schema and palette/grid data; recognition metadata is not added to saved Workspace cells.

## Annotated cell evaluation

[`cell-annotations.json`](../tests/fixtures/mard/cell-annotations.json) contains 169 visually transcribed source cells: 39 Pig, 61 Duck, 69 Teapot; 131 occupied and 38 empty. It covers all represented color identities, dark and saturated cells, pale cream, printed occupied-white cells, empty white/shadows/holes, code lettering and watermarked regions. These are assistant-created diagnostic annotations, not an independently human-certified or blinded held-out benchmark. Several caption/column transcription errors were corrected by reinspection of the source contact sheet before freezing the annotations.

Color identity is checked against separate manually located **5×3-pixel source legend patches** excluding printed labels. Coordinates, median RGB swatches and labels are test-only. Evaluation maps a predicted palette representative to the nearest reference swatch in OKLab within 0.06; it does not fit a majority mapping from the evaluated cell labels or change any production classification. These are image-level swatches, not calibrated MARD color values.

Automatic, manual and all four translated-crop runs each achieve 131/131 true occupied, 38/38 true empty, and 131/131 correctly associated occupied-color identities **on this targeted subset only**.

Color accuracy includes missed occupied cells as failures, rather than considering only detected true positives. Predictions flagged uncertain are still included in the accuracy denominator and separately reported. Exact full-chart cell ground truth remains unavailable. The subset was used for diagnosis and validation, so a broader unseen-chart study is still needed.

## Performance and memory

| Chart | Baseline → current median classification | Ratio | Baseline → current peak diagnostic-process RSS | Current full automatic analysis |
|---|---|---|---|---|
| flying-pig | 434 → 658 ms | 1.52× | 200.7 → 259.8 MiB | 2520 ms |
| duck-copy | 222 → 285 ms | 1.28× | 126.3 → 175.6 MiB | 826 ms |
| teapot-copy | 179 → 267 ms | 1.49× | 121.9 → 178.3 MiB | 745 ms |

Raw timings, RSS and GC heap observations are retained in the cell-validation JSON. Heap deltas can be negative when V8 reclaims earlier diagnostic allocations, so they must not be interpreted as reduced result memory or exact retained object sizes.

Timing uses the same browser-decoded raster in separate Node processes for the baseline and current classifier, with known manual geometry to exclude grid inference. Three warmed calls are measured; their median is reported. Peak RSS covers the **entire isolated diagnostic process**, including raster JSON decoding, automatic grid analysis, results and crop-variation probes; it is not classifier-only peak allocation or native mobile memory. The after-GC heap delta includes a retained recognition result and runtime variation; it is not a precise object-size measurement. Browser Worker/UI timings are also recorded separately in real-copies/results.json and include scheduling, rendering and test contention.

The new classifier is more expensive than the old single-region threshold sampler. It remains in the existing cancellable Web Worker. The source RGBA buffer remains 13.22 MiB for Pig and 5.17 MiB per copy; temporary sampling and metadata increase process memory. Worst-case 20-megapixel inputs and native iPhone latency/memory have not been benchmarked.

## Remaining limitations and isolation

- Identical unlabelled white pixels cannot establish whether a cell is a bead or a hole; provisional empties in a beaded neighborhood are explicitly uncertain. Shadows or dense centered markings can still resemble occupied white.
- Very close colors, heavily obscured cells, tinted paper, severe compression and dense text remain review cases. Generalization beyond these fixtures and synthetic cases is not established by count agreement.
- The existing compressed synthetic grid probes still abstain automatically and recover via manual geometry; this classification round does not claim a grid-detection fix.
- Existing mobile Workspace screenshots show the Complete label wrapping; Workspace styling is unchanged and that pre-existing presentation is outside this classification round.
- No OCR, perspective correction or full-chart certified cell accuracy is claimed. Official palette codes still require manual review.
- `src/gridDetection.ts`, crop geometry/interaction modules, Workspace implementation/CSS, Project schema, storage module and Pages workflows are unchanged. B1 continues using only `pindou.preview.v20b1.projects.v1`.
- Approved V1.5/V2A Pages deployment and the production repository/site are untouched. This change is committed locally on the B1 feature branch and is **not deployed**.
