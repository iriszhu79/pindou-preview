## Baseline findings before algorithm changes

The original `diagnoseLegacyGrid` implementation remains available for comparison. Full baseline copy evidence is in [`baseline-copies/`](previews/v20b1/baseline-copies/); ranked diagnostics also retain the complete legacy result.

| Fixture | Measured V2.0-A baseline on available pixels | Difference from native screenshot |
|---|---|---|
| Pig | 103 X peaks / 67 Y peaks, 29.7px on both axes; 40×51 accepted; 1179 beads | Previously supported repository image |
| Duck copy | 20 X peaks / 16 Y peaks; 90.5px both axes; **wrong 10×10 accepted**, only 2 classified beads | Does **not** reproduce the original skew exception; exposes a silent major-line alias instead |
| Teapot copy | X span336–986 at18px, 37 selected lines; Y search has10 peaks and no accepted chain; rejected at **Y-axis** stage | Same ambiguous-grid message category as screenshot, not proof of exact native-file replay |

Confirmed architectural causes on these copies:

1. Baseline gray projection excludes luminance above247 and strongly favors heavy lines through global maximum-relative floors and summed-strength ranking. Duck's pale fine lines lose to five-cell separators; the accepted 90.5px period is about five true cells.
2. Each axis returns only one chain. Missing evidence ends a chain, and no joint candidate competition can correct a bad X choice.
3. Y sampling is restricted to edge bands derived from that X choice. Teapot has no continuous internal gray grid, and the selected partial X span does not provide a reliable Y lattice.
4. Numbered axes and colored block boundaries were not independent sources of geometry evidence.

The native Duck error is produced by the old post-selection X/Y ratio guard (outside0.86–1.16), but its actual native selected periods remain unknown. Resizing/transforming copies can change line strengths and which alias wins; it would be incorrect to report that original exception as reproduced here.

## Generalizable changes

New pure module: `src/gridDetection.ts`.

- Samples **every possible line position**; subsamples only the orthogonal direction. Odd-coordinate lines are not discarded.
- Gray-line evidence includes pale levels and clips per-pixel contrast to reduce major/fine weight dominance.
- Fits multiple periodic lattices, tolerates bounded gaps, refits spacing by regression, and removes truncated subsets of the same supported lattice.
- Finds paired periodic small-glyph bands around a candidate chart. These provide numbered-axis/border evidence without decoding digit values or performing legend OCR.
- Evaluates both boundary-labelled and center-labelled axis conventions, spatial border alignment, X/Y square-cell agreement, coverage and image phase.
- Generates color-transition lattice proposals and uses transition phase to rank geometries. Color-block extent alone remains unverified: it cannot invent missing empty margins.
- Penalizes coarse harmonic aliases **only when intermediate fine-line image evidence supports a finer lattice**. It does not assume every major line represents five cells.
- Checks boundary continuity to reduce header/legend/text extensions. Strong colored transitions contradicting a coarse proposal cause an explicit uncertain-geometry/manual-review result.
- Retains the legacy proposal as one candidate and corroborates independently agreeing line proposals. Competing dimensions with similar evidence cause abstention.
- Exposes alternative candidates in a collapsed UI; selecting one invalidates results and still requires re-analysis and explicit review.

No chart names, hashes, expected counts, known 40/50/51 dimensions, fixed chart locations, official color codes or reference quantities are used in production detection. No source-image resizing/distortion, external image service, OpenCV dependency, or legend OCR was introduced. The cell classifier is intentionally unchanged.

## Synthetic coverage and abstention

`tests/grid-variants.ts` generates non-reference-sized charts (37×43 and29×41), centered24-bead patterns with large empty areas, pale lines (248–252), heavier lines every5/10 cells, headers/legends, two absent lines, and cropped page margins. Exact grid dimensions and crop alignment are asserted; classification with specified geometry yields24 beads. Existing20×20,40×51 and120×100 ground-truth classification tests also remain green.

A separate color-block-only fixture verifies that a colored region cannot certify unknown full-chart bounds.

Actual browser JPEG encode/decode at quality0.92 and0.82 is tested in `tests/compressed-grid.mjs`. Both variants **abstain automatically** (ambiguous or color-period conflict) and recover24 beads with manual geometry. Compression is therefore a remaining automatic-detection limitation, not an automatic success claim. The0.82 probe initially exposed a wrong accepted coarse alias; the color-period contradiction check now rejects it. Encoded synthetic images and measured results are under [`synthetic/`](previews/v20b1/synthetic/).

## Safety and unresolved scope

No deployment, merge into preview main, production modification, or Pages workflow change. Approved preview main remains `8cea1e5a33db4c936fbeb3cf1007210ff6e45735`; V2.0-A source remains `86f58af`. B1 reads/writes only `pindou.preview.v20b1.projects.v1`, never approved-version keys; regression data exists only in disposable browser contexts.

Native originals1440×1672 remain untested. Arbitrary perspective/skew, fewer paired labels, extensive cropping/occlusion, stronger compression, and difficult low-contrast charts may still require manual alignment. Axis inference recognizes periodic glyph placement, not numeric semantics; repeating decoration can remain ambiguous. Custom image pinch is not implemented; zoom slider and inspect/pan remain available. Accurate saturated/pale cell classification and palette recovery are unresolved; full legend OCR is not started.
