# V1.2 workspace QA

## Scope and preservation

Built on `main` after PR #4 (V1.1 tools), retaining strategy preview, rectangular grids, cell completion, undo, LocalStorage, Hand/Select, Space-panning, pinch, and modifier-wheel zoom. Deployment workflow, original pattern, reference images, PRD, and stored project schema are unchanged. The studio and overview still scroll normally; the crafting workspace occupies the viewport and never requires page scrolling between the pattern and essentials.

## Automated validation

- Node.js 24: clean `npm ci`, `npm test` (9 passing model/focus tests), `npm run build`.
- `npm run test:browser`: Chromium input regression, strategy/rectangular-grid checks, and mobile-session acceptance checks. Run against a dev server or set `PINDOU_TEST_URL` to a local production preview under `/pindou/`.
- Tested CSS viewports: 390×844, 375×667, 844×390, 667×375, 820×1180, 1180×820, 1440×900, 1280×800. An additional 640×400 layout checks the reduced CSS space comparable to 200% zoom on a 1280×800 window; it is not a real OS/browser zoom test.
- At every session-test viewport: ten consecutive steps, current coordinate/counts/chips/navigation/completion visible, no document scrolling or horizontal overflow, no panel covering the canvas, separate navigation and completion, real Chromium touch-input pan/pinch, Focus Mode entry/exit, selected-tool/zoom/progress retention during rotation, manual focus, refresh, unrelated saved-project preservation, and a synthetic 40-column × 51-row pattern.
- Reused V1.1 browser tests cover individual mouse/touch bead completion, accidental-drag suppression, Space shortcut, undo, reversed row/column navigation, empty steps, Fit, and original input regression behavior.
- Unit tests verify minimal offscreen-step correction and no movement for visible rows/columns. Reduced-motion behavior is checked in Chromium.
- Screenshots are generated under `/tmp/pindou-v12-<width>x<height>.png` for review, outside the repository. The production build must pass the same browser suites before delivery.

## Layout behavior

- Portrait phones/tablets: compact toolbar, flexible canvas, persistent bottom task dock. Details expand inside a bounded scroll region; essential counts/colors/navigation/completion remain outside that region.
- Landscape phones: compact canvas + 242px side panel; tablets/desktop use a larger 300px side panel. Directional controls stay in canvas chrome, outside the transformed grid.
- Focus Mode hides optional details, decorative tags/help, and the project-back control. Exit Focus stays visible. Progress, tools, color quantities, navigation, and completion remain available.
- Automatic focus reveals an offscreen step with minimal translation; already-visible steps retain pan. Manual Focus centers the strip. Orientation changes remeasure the actual canvas and preserve the zoom factor, tool, step, and cells.
- Safe-area padding and `100dvh` protect device edges; `100vh` is the fallback. No fullscreen/orientation-lock API is required.

## Limits / follow-up acceptance

These are automated Chromium viewport/input tests, not physical-device certification. Review Safari's expanding/collapsing toolbar, iPhone home-indicator/notch insets, physical iPad pinch/orientation, real browser zoom, and Mac trackpad feel on devices. Headless viewports do not simulate nonzero iOS safe-area insets. Unusually large palettes may scroll within the color-chip region; optional details scroll independently. Browser gesture/browser UI differences remain possible.

No image recognition or real 40×51 chart transcription was added. Large-grid data is explicitly synthetic and confined to tests. LocalStorage is per browser/origin and provides no cross-device synchronization. Complete & Next was intentionally omitted; the separate completion and Next actions remain explicit. No manual deployment or automatic merge is part of this change.
